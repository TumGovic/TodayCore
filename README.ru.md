# TodayCore

**TodayCore** — экспериментальное сетевое ядро на базе **sing-box 1.15.0-alpha.6**. Проект сохраняет архитектуру и формат конфигурации sing-box и добавляет современные возможности Xray-core, необходимые для работы с актуальными развёртываниями Xray — как в роли клиента, так и в роли сервера. Возможности перенесены из **Xray-core 26.9.9 и 26.9.30**.

> [!WARNING]
> TodayCore находится в beta-стадии и развивается сообществом. У проекта нет фиксированного графика релизов, гарантированной совместимости или коммерческой поддержки. Проверяйте каждое обновление перед использованием в рабочем окружении.

## Зачем нужен TodayCore

TodayCore обеспечивает совместимость sing-box с актуальными развёртываниями Xray без попытки полностью скопировать Xray. Рассматриваются только современные и практически полезные функции; устаревшие и legacy-протоколы намеренно не входят в область проекта.

## Основное

- **XHTTP** — клиент и сервер, все режимы, HTTP/1.1, HTTP/2 и HTTP/3.
- **REALITY**, совместимый с серверами Xray 26.9, включая проверку ML-DSA-65 и «паука».
- **Постквантовое шифрование VLESS** (`mlkem768x25519plus`) для outbound и inbound, с XTLS Vision.
- **FinalMask** со всеми TCP- и UDP-масками Xray.
- **Browser dialer**, чтобы трафик XHTTP и WebSocket отправлял настоящий браузер.
- **Генераторы ключей**, совместимые с `xray vlessenc` и `xray mldsa65`.

## Что добавлено поверх sing-box

### Транспорт XHTTP

Транспорт Xray SplitHTTP/XHTTP для outbound и inbound:

- режимы `packet-up`, `stream-up`, `stream-one` и `auto`;
- HTTP/1.1, HTTP/2 (TLS и h2c) и HTTP/3, если TLS ALPN равен ровно `["h3"]`;
- размещение метаданных сессии в path, query, header или cookie;
- отправка uplink-данных в body, header или cookie;
- X-Padding с настраиваемыми размещением, ключом, заголовком и обфускацией;
- стандартные заголовки, похожие на браузерные;
- настройки повторного использования соединений и запросов XMUX;
- отдельные `downloadSettings`;
- сервер, принимающий любой режим, который может выбрать клиент Xray.

### REALITY

Клиент REALITY работает с серверами Xray-core 26.9:

- отправляет гибридный key share `X25519MLKEM768` перед обычным `X25519`, как требуют современные серверы;
- сообщает совместимую версию клиента `26.9.9` и не попадает в fallback `reality verification failed` на серверах, требующих современный клиент;
- `mldsa65_verify`: постквантовая проверка ML-DSA-65 для серверов с `mldsa65Seed`;
- `spider_x`: «паук» Xray, который продолжает обход целевого сайта после получения настоящего сертификата.

Поведение key share и версии включается автоматически при использовании REALITY с uTLS.

### Постквантовое шифрование VLESS

VLESS Encryption из Xray для outbound (`encryption`) и inbound (`decryption`):

- `mlkem768x25519plus` с режимами `native`, `xorpub` и `random`;
- рукопожатия `1rtt` и `0rtt` со сроком действия тикетов;
- профили padding;
- ключи X25519 и ML-KEM-768, включая цепочки relay-ключей;
- XTLS Vision (`xtls-rprx-vision`) поверх слоя шифрования.

Считайте эту возможность экспериментальной до прохождения более широкого тестирования совместимости.

### FinalMask

Все маски FinalMask из Xray:

- **TCP:** `fragment`, `sudoku`, `header-custom`, `xmc`;
- **UDP:** `noise`, `salamander` (включая Gecko), `sudoku`, `header-custom`, `mkcp-legacy`, `udphop`, `xdns`, `xicmp`, `realm`.

Добавьте объект `finalmask` в параметры inbound или outbound. Он оборачивает «сырые» TCP/UDP-сокеты под TLS и транспортом — так же, как `streamSettings.finalmask` в Xray, — и использует имена полей Xray.

### Browser dialer

Browser dialer из Xray для исходящих XHTTP и WebSocket: TodayCore поднимает локальную страницу, и браузер, в котором она открыта, выполняет запросы со своим собственным TLS- и HTTP-отпечатком. Включается для каждого транспорта через `browserDialer` (XHTTP) или `browser_dialer` (WebSocket).

### Генерация ключей

```bash
sing-box generate vlessenc
```

```bash
sing-box generate mldsa65-keypair
```

Первая команда выводит согласованные строки VLESS `decryption`/`encryption`, как `xray vlessenc`. Вторая выводит seed ML-DSA-65 для серверов REALITY на Xray и ключ проверки для клиентов, как `xray mldsa65`.

## Статус переноса функций

| Функция Xray | Статус в TodayCore | Примечание |
| --- | --- | --- |
| XHTTP клиент и сервер | Перенесено | Все режимы; HTTP/1.1, h2, h2c, HTTP/3 |
| XHTTP metadata placement, X-Padding, XMUX | Перенесено | Имена полей совместимы с Xray |
| Browser dialer | Перенесено | Исходящие XHTTP и WebSocket |
| Совместимость REALITY с `X25519MLKEM768` | Перенесено | Автоматически для поддерживаемых uTLS fingerprints |
| REALITY `mldsa65Verify` и `spiderX` | Перенесено | Клиент (`mldsa65_verify`, `spider_x`) |
| VLESS Encryption | Экспериментально | Outbound (`encryption`) и inbound (`decryption`) |
| FinalMask | Перенесено | Все TCP- и UDP-маски; inbound и outbound |
| REALITY `mldsa65Seed` (сервер) | Не перенесено | Сервер REALITY в sing-box не умеет подписывать ML-DSA-65; используйте сервер Xray |

Все перенесённые возможности протестированы против Xray-core 26.9.30 в обоих направлениях. У нескольких масок есть ограничения окружения, описанные в руководстве по расширениям: `xicmp` требует raw-сокетов, `realm` — сигнального сервера, а `xdns` передаёт только небольшие пакеты.

## Конфигурация

TodayCore использует JSON-формат конфигурации sing-box. Поля, пришедшие из Xray (параметры XHTTP и настройки FinalMask), сохраняют написание Xray, поэтому эти части конфигурации Xray можно использовать без изменений.

- [Расширения TodayCore и примеры конфигурации](docs/todaycore-extensions.md)

Оригинальная документация sing-box сохранена в каталоге [`docs/`](docs/). Для полей, которых нет в отдельном руководстве TodayCore, используйте документацию sing-box 1.15.

## Сборка

### Требования

- Go **1.25.5** или совместимая более новая версия;
- Git;
- `make` для стандартного процесса сборки.

### Стандартная сборка

```bash
make
```

Установка в `$GOBIN`:

```bash
make install
```

Выбранные build tags можно передать через Makefile:

```bash
TAGS="with_quic with_utls" make
```

Стандартные build tags и необходимые linker flags находятся в `release/DEFAULT_BUILD_TAGS*` и `release/LDFLAGS`. Если вам не нужны особые платформенные настройки, предпочтительно использовать стандартную цель `make`. Для XHTTP через HTTP/3 нужен `with_quic`, для REALITY — `with_utls`; оба входят в стандартные теги.

## Статус разработки и участие

TodayCore поддерживается **исключительно на добровольной основе**. Разработка может надолго приостанавливаться. Нет обещаний, что изменения из новых версий sing-box или Xray будут переноситься немедленно.

Если вы хотите, чтобы проект активно развивался, проявляйте инициативу:

1. тестируйте TodayCore с актуальными серверами и клиентами Xray;
2. сообщайте о воспроизводимых проблемах совместимости;
3. прикладывайте логи, версии клиента и сервера, а также очищенную от секретов конфигурацию;
4. добавляйте тесты протокола и wire format;
5. отправляйте pull request с небольшим и понятным изменением.

Полезные коммиты и pull requests — лучший показатель реального интереса к продолжению разработки. Вклад сообщества приветствуется и напрямую влияет на скорость развития проекта.

По возможности делайте pull requests небольшими, описывайте поведение, которое переносится, и добавляйте ссылку на соответствующую реализацию или спецификацию Xray.
